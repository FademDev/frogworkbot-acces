# Minecraft Whitelist Discord Bot

## Требования
- Node.js 22 или новее
- Discord application и bot token

## Установка
1. Распакуй проект в отдельную папку.
2. Выполни `npm install`.
3. Скопируй `.env.example` в `.env` и укажи `DISCORD_TOKEN`.
4. Заполни `config.json`: Discord guild ID, все ID ролей, ID администраторов.
5. В Discord Developer Portal включи **Server Members Intent** и **Message Content Intent**.
6. Запусти `npm start`.

## RCON whitelist и /zwl
- Slash-команда `/zwl add nick:<ник>` добавляет Java-ник через RCON командой `config.json` → `rcon.command_template` (по умолчанию `zwl add {nick}`).
- Пароль считывается из `.env` по имени `rcon.password_env` (сейчас `RCON_PASSWORD`). Не публикуй `.env`.
- Команда ограничена пользователями из `discord.panel_admin_ids`; ник проверяется до отправки RCON-команды.
- Для личных сообщений включи **Direct Messages** и **Message Content** intents, а для обнаружения ролей — **Server Members Intent** в Discord Developer Portal.


## Выдача проходок
- `discord.access_role_ids` — перечисление всех ролей, выдача любой из которых автоматически запускает процесс платной проходки.
- `discord.role_access_types` — сопоставление каждой такой роли со значением `paid`. Бесплатные роли сюда добавлять не нужно.
- Бесплатная проходка выдаётся только вручную через `!панель`, без привязки к Discord-роли.
- Платная и бесплатная заявки используют одинаковую дальнейшую процедуру: ник → заявка администраторам → кнопка подтверждения.

## Пиратские/offline-mode серверы
- `minecraft.check_profile_exists` установлен в `false`: бот не обращается к Mojang/Minecraft для поиска профиля.
- Проверяется только допустимый формат ника Java Edition: 3–16 символов, латинские буквы, цифры и `_`. Это совместимо с никнеймами на offline-mode серверах.
- Форматная проверка не может подтвердить, что ник действительно занят конкретным игроком на сервере.

## Администраторы
- `discord.admin_ids` — кому отправлять заявки и кто может нажимать «Я добавил».
- `discord.panel_admin_ids` — кто может использовать `!панель`.

## Примечания
- Бот автоматически добавляет ник из заявки через RCON, если `rcon.auto_whitelist` включён. Для ручного добавления администратором доступна команда `/zwl add nick:<ник>`.
- Не публикуй `.env` и не отправляй токен другим людям.

## Правила проекта
- Текст правил хранится в `rules.js` (`RULES`). Нумерация разделов и пунктов проставляется автоматически при сборке embeds, поэтому при добавлении пунктов вручную нумерацию править не нужно.
- `!правила` (или `!rules`) — бот отправляет правила в личные сообщения. Уведомление о доставке в канале автоматически удаляется через `rules.notice_delete_after_ms`.
- `/правила` — альтернатива: правила приходят эфемерным ответом, то есть видны только вызвавшему участнику.
- Кулдаун на запрос правил задаётся в `config.json` → `rules.cooldown_seconds` (по умолчанию 100 секунд, то есть 1 мин 40 с). Кулдаун общий для `!правила` и `/правила`, хранится в `data/requests.json` и не сбрасывается при перезапуске.
- Ключ `rules.enabled: false` полностью выключает команду, `rules.register_slash_command: false` — только регистрацию `/правила`.
